# Design-sync notes — SystemWeavers

## Repo shape

This is a Next.js marketing site, not a published component-library package.
There's no `dist/` build, no barrel `index.ts`, and no Storybook. A dedicated
build was added specifically for design-sync:

- `design-system/entry.ts` — barrel exporting the synced components.
- `tsup.config.ts` — builds `design-system/entry.ts` → `dist/index.js` +
  `dist/index.d.ts` (`.d.mts` is also emitted by tsup; `.d.ts` is a copy made
  by the `build:ds` script since tsup's `outExtension` override didn't apply
  to the dts output in tsup 8.5.1 — the `node -e copyFileSync` step in
  `package.json`'s `build:ds` script handles it).
- `design-system/build-css.mjs` — tsup does not run Tailwind. This script
  runs `app/globals.css` through `@tailwindcss/postcss` directly (same plugin
  Next.js uses) to produce `dist/styles.css`, the real compiled utility CSS.
  Without this, previews would render with zero Tailwind classes applied.
- Run both via `npm run build:ds` (this is `cfg.buildCmd`).

## Next.js shims (design-system build only — production app untouched)

`tsup.config.ts` aliases these to `design-system/shims/` and forces `next` to
bundle (`noExternal: ["next"]`) so the alias can intercept the subpaths —
tsup treats `next` as external by default since it's in `package.json`
`dependencies`, which silently skips any alias unless overridden:

- `next/link` → plain `<a>` (no client-side router exists standalone).
- `next/navigation` (`usePathname`) → returns `"/"`. Only `Header` uses this,
  to bold the active nav link; there's no real route outside the Next app.
- `next/image` → plain `<img>`, resolving known site photos through
  `design-system/shims/image-map.ts`.

## Inlined images

`about-page.tsx` and `get-to-know-us.tsx` reference photos via absolute
`/images/*.png` paths that only resolve on the real site's own server — an
isolated bundle has nothing to serve them. `image-map.ts` imports the three
files directly (`public/images/{about-hero,founder-grisel,founder-monica}.png`)
with esbuild's `dataurl` loader, so they're baked into `dist/index.js` as
base64. This is why the bundle is ~3.2 MB instead of ~65 KB — expected, not a
bug.

**Re-sync risk**: if these photos are replaced/added, `image-map.ts` needs
its imports and the map keys updated to match. If image count/size grows a
lot, consider hosting them properly instead of inlining.

## Excluded components

`Providers` (context-wrapper only, no visual output) and `HashScroll`
(`return null` — pure scroll side-effect) were excluded from
`design-system/entry.ts` — confirmed with the user. They have nothing to
preview by design, not because of a build limitation.

## Scope

Synced: Button, TextInput, TextTextarea, Icon, Header, Footer, Selvage,
SelvageMark, ContactForm, HomePage, GetToKnowUs, AboutPage — full scope
including page-section compositions (HomePage, AboutPage), per explicit user
choice, not just the small `components/ui/` primitives.

## Fonts

`--font-fraunces`/`--font-public-sans` are set by `next/font/google` on
`<html>` in `app/layout.tsx`, which isn't part of `design-system/entry.ts` —
so components reference those variables but nothing in the compiled
Tailwind output defines them. `design-system/build-css.mjs` prepends a
Google Fonts `@import` + `:root` variable definitions to `dist/styles.css`
to fix this (validate confirms via `[FONT_REMOTE]`, informational). This is
separate from the real site's fonts, which stay correctly self-hosted via
next/font — this fix only affects the design-sync bundle.

**Re-sync risk**: if the real site changes font weights/styles/families,
update the `FONTS_PREAMBLE` Google Fonts URL in `build-css.mjs` to match.

## Known render warns

- `[RENDER_THIN] Icon` — "mounts have no text and paint nothing" fires even
  after authoring `Icon.tsx` (Gallery + HeartHandshake cells). This is a false
  positive: icons are pure SVG strokes with no text content by nature: the
  screenshots confirm both cells render correctly (teal icon glyphs, correct
  size/stroke). Triaged as benign — a re-sync seeing this exact warn is not
  new.

## Re-sync risks

- `cssEntry` (`dist/styles.css`) depends on Tailwind's automatic content
  detection scanning the whole repo from `app/globals.css`'s location when
  `build-css.mjs` runs `postcss` — if components move outside the scanned
  tree, classes could silently stop being generated.
- The three Next.js shims are hand-maintained duplicates of a subset of real
  `next/link` / `next/image` / `next/navigation` behavior. If a synced
  component starts using a next/navigation hook other than `usePathname`, or
  next/image props beyond `fill`/`sizes`/`priority`, the shim needs updating.
- `dist/` and `.ds-sync/` are gitignored and regenerated by `buildCmd` — never
  hand-edit files in `dist/`.
